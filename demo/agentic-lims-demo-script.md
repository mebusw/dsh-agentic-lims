## 1. 输入（现场粘贴给 Agent）

```text
你是智能实验室（Agentic LIMS）的排程助手。按三步走，不要跳步；所有事实必须来自 lims_* 工具，不要编造任务编号、工时、设备状态或可用时段。

【原始需求（计划员口语）】
"PRJ-1001 下周的拉伸和耐久测试优先保交期，模板用 TPL-004；TASK-2004、TASK-2006 这两个零散任务也一起排，能复用已有任务就别新建。"

【第 1 步｜先拆解，不要排程】
1. 用 lims_list_projects / lims_get_project 读 PRJ-1001 的任务、模板分组、交期、已有计划。
2. 用 lims_prepare_task_draft（projectId="PRJ-1001"，templateId="TPL-004"，requestText 用上面原话）拆解需求。
3. 输出对应表：request 片段 → 项目 → 模板 → 候选 TASK_ID → 判断依据 → 把握度 → 缺失字段。
4. 引擎会附带一条"新建任务草稿"：明确说明是否采纳（已有任务能覆盖就不建，不写库）。
5. TASK-2004 / TASK-2006 如果不属于 PRJ-1001，标出真实归属，按"独立任务搭车排程"处理，不要塞进同一个测试计划，也不要新建任务。
6. 停下来等我确认对应关系，此时不要生成任何方案。

【第 2 步｜确认对应关系后再排程】
我说"确认对应关系"后：
a) lims_generate_test_plan（projectId="PRJ-1001"，templateId="TPL-004"）；
b) lims_generate_plans（taskId="TASK-2004"）；
c) lims_generate_plans（taskId="TASK-2006"）。
每次排程后说明：完成时间、是否晚于交期、阻塞项、设备/人员/空间占用、风险。有阻塞就解释诊断，不要把阻塞说成可行。

【第 3 步｜汇总】
用一张表汇总：任务 | 时间 | 设备 | 人员 | 空间 | 冲突/风险 | 方案编号 | 状态（候选/已确认）。
候选方案只写入 MongoDB，尚未确认；告诉我三种确认入口（聊天卡片「确认此方案」按钮 / 右侧「候选方案 · 尚未确认」横幅 / 回复"确认方案 <ID>"）。只有我明确说确认，才调用 lims_confirm_plan。

【红线】
- 不编造 TASK_ID、工时、设备状态、可用时段；
- 不调用 lims_create_task_draft，除非我明确说"创建这些任务"；
- 不自动确认任何方案。
```

## 2. 拆解思路（五个节拍）

| 节拍 | 动作 | 产出 | 是否写库 |
|---|---|---|---|
| ① 定位 | `lims_list_projects` → `lims_get_project(PRJ-1001)` | 2 任务 / 34h / TPL-004 单分组 | 否 |
| ② 拆解 | `lims_prepare_task_draft` | 匹配表（编号 / 模板 / 依据 / 置信度）+ 附带草稿 + 缺失字段 | **否** |
| ③ 判断 | Agent 解释"草稿不采纳"、"2004/2006 跨项目，单独排" | 复用结论 | 否 |
| ④ 闸门 | 停下来等客户确认对应关系 | 人工决策点 | 否 |
| ⑤ 排程 | `lims_generate_test_plan` + `lims_generate_plans` ×2 | 候选方案 + 甘特图 + 约束校验 | 只写候选 |

## 4. 幻灯片文案（可直接复制）

### 第 1 页 · 输入

- **一句计划员口语**：
  > "PRJ-1001 下周的拉伸和耐久测试优先保交期，模板用 TPL-004；TASK-2004、TASK-2006 这两个零散任务也一起排，能复用就别新建。"
- **只有四类信息**：项目编号、模板、两个零散任务编号、优先目标（保交期）
- **没有**：工序步骤、设备选择、时间安排、人员指派——这些由系统补齐

### 第 2 页 · 拆解思路

1. **定位**：项目 → 模板分组 → 任务清单（PRJ-1001 / TPL-004 / 2 任务 34h）
2. **只读拆解**：匹配已有任务，给出依据与置信度；缺失字段标出来问人
3. **拒绝重复**：引擎建议新建一条 2.5h 草稿 → 判定被已有任务覆盖 → 不建
4. **跨项目识别**：TASK-2004（PRJ-1003）、TASK-2006（PRJ-1005）不在本项目 → 单独排，不混进测试计划
5. **人工闸门**：对应关系确认后才排程
6. **确定性排程**：按优先级 + 交期，自动避让设备/人员/空间冲突
7. **候选不落地**：只写候选，确认后才占资源、写审计

### 第 3 页 · 预期输出

- **PRJ-1001 测试计划**：2/2 已排，34h，**0 阻塞、0 晚交期**
  - TASK-2001：10/27 08:00 → 10/29 10:00｜EQ-007 + 赵敏
  - TASK-2002：10/29 14:00 → 11/03 12:30｜EQ-007 + 赵敏
- **TASK-2004**：10/27 08:00–16:00｜EQ-006 + 陈晨 + SP-003
- **TASK-2006**：10/27 09:00–13:00｜EQ-001 + 张伟 / 刘洋 + SP-002（2 个候选）
- **收尾**：4 个任务 4 份候选，右侧甘特图 + 约束校验，等一句"确认"

## 5. 现场 Q&A 预判

| 客户可能问 | 建议回答 |
|---|---|
| 为什么从 10/27 开始，不是下周一？ | 引擎按"最早可行 + 交期优先"排；要严格下周一可以加约束重排 |
| 为什么这两条不在 PRJ-1001 里？ | 它们是历史任务，归属别的项目；作为"零散任务搭车"单独排，不污染项目测试计划 |
| 为什么不干脆新建任务？ | 已有任务能覆盖同一需求；重复建会造成同一批样品排两次、占两份机时 |
| 阻塞了会怎样？ | 引擎会给诊断（窗口、设备、人员、资质），不会把不可行说成可行 |
| 确认后真的排产了吗？ | 原型只写模拟占用与审计记录，不接生产系统 |
